:title
6. Strings and HTML

:content
Use strings for text and markup expressions for HTML. Markup escapes ordinary strings before they enter the response.

## Escape dynamic text

:example capy render
function RENDER(request : dval) {
    var name := "<Ada>"
    print(<><p>Hello, <?= name ?></p></>, "\n")
}

:output
<p>Hello, &lt;Ada&gt;</p>

:content
`<?= name ?>` selects an encoding from its location. HTML text and quoted attributes escape `&`, `<`, `>`, quotes, and apostrophes.

Inside a `script` element, a string becomes one self-contained JavaScript literal. The encoder protects the closing tag and JavaScript line separators. Inside a `style` element, a string becomes one self-contained CSS literal. Integer and Boolean values remain scalar values. `f64` interpolation is not supported in these elements.

:example capy render
function RENDER(request : dval) {
    var name := string(request.query.name, {fallback: "guest"})
    print(<>
        <script>const name = <?= name ?>;</script>
        <style>.name::before { content: <?= name ?>; }</style>
    </>)
}

:content

Script and style interpolation must start at a value boundary. Static source after it can apply an operator or a CSS unit. Do not put interpolation inside an existing string, template literal, or comment. Attribute values must use quotes. Tag and attribute names cannot contain interpolation.

URL, event-handler, and inline-style attributes use HTML attribute escaping. Validate these values for their application context before interpolation.

## String literals

String literals use double quotes:

:example capy render
function RENDER(request : dval) {
    var message := "Hello"
    var line := "first\nsecond"
    print(message, " ", line, "\n")
}

:content

The supported escapes include `\n`, `\r`, `\t`, `\"`, and `\\`. String positions and lengths count bytes, not Unicode characters.

Use `+` to join strings:

:example capy render
function RENDER(request : dval) {
    var name := "Ada"
    var greeting := "Hello, " + name
    print(greeting, "\n")
}

:content

Use a constructor to convert a scalar when a function does not already accept `as string`:

:example capy render
function RENDER(request : dval) {
    var label := "Count: " + string(3)
    print(label, "\n")
}

:content

## Markup expressions

A markup expression starts with `<>` and ends with `</>`:

:example capy render
function RENDER(request : dval) {
    var title := "Report"
    print(<>
        <h1><?= title ?></h1>
        <p>Ready</p>
    </>)
}

:content

The expression has type `markup`. It is a value. It does not write to the response by itself. Use `print(markup_value)` to output it. You can also return `markup` from an ordinary function or insert it into other markup.

:example capy render
function badge(label : string) markup {
    -> <><strong><?= label ?></strong></>
}

function RENDER(request : dval) {
    print(badge("Ready"))
}

:output
<strong>Ready</strong>

:content

## Interpolation rule

`<?= value ?>` escapes output at the interpolation site. `<?: value ?>` emits output without escaping. It works only in HTML text.

The interpolation form selects escaping. The value type does not.

## Common string operations

Use `length`, `substr`, `find`, `contains`, `replace`, `lower`, `upper`, `split`, and `join` for ordinary text work. Use `html_escape` when an API needs escaped text instead of a `markup` value.

Strings use automatic reference counting. Assignment and function calls preserve their lifetime. Most programs do not need to call `clone`.
