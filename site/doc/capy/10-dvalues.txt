:title
10. DValues

:content
A `dval` is a dynamic value for Bearer APIs. It can hold an empty value, string, boolean, number, map, or list. Use DValues for request data, JSON, database rows, component properties, task messages, and unit calls.

## Creating DValues

A map literal creates a DValue directly:

```capy
var profile := {
    name: "Ada",
    "active": true,
    tags: ["math", "logic"]
}
var empty_map := {:}
```

A map key can be an identifier or a quoted string. The `dval({...})` compatibility spelling remains valid.

Use `dval(...)` to create a DValue from a string, `s32`, `u64`, `f64`, `bool`, existing DValue, or list literal. A list inside `dval(...)` becomes a dynamic DValue list. A bare list remains a typed `[T]` array.

## Reading values

Use member syntax for an identifier key. Use brackets for other string keys, dynamic keys, and list indexes:

```capy
var name := dval_string(profile.name)
var first_tag := dval_string(profile.tags[0])
var display_name := dval_string(profile["display-name"])
```

Member access and indexing are strict. A missing key, wrong container type, or invalid list index traps. Check optional data before you read it:

```capy
if dval_has(profile, "nickname") {
    print(dval_string(profile["nickname"]))
}
```

Strict extraction functions include `dval_string`, `dval_bool`, `dval_s32`, and `dval_f64`. Select the function for the value you expect. `dval_f64` also accepts a complete finite numeric string because Bearer's JSON decoder preserves JSON numbers as strings.

Conversion functions such as `dval_to_string`, `dval_to_bool`, `dval_to_f64`, `dval_to_s64`, and `dval_to_u64` support documented fallback overloads. The wide-integer forms preserve exact 64-bit results.

## Iteration

A map loop provides each string key. A list loop provides each numeric index:

```capy
for key, value = profile {
    print(key, " = ", dval_to_string(value), "\n")
}
```

A map loop visits keys in lexical order. A list loop visits indexes in numeric order.

## Updating values

DValue update functions return a replacement value. Assign the result:

```capy
var items := dval([])
items = dval_push(items, dval("first"))
items = dval_push(items, dval("second"))
```

This rule also applies to `dval_set`, `dval_remove`, `dval_clear`, and related functions. Arbitrary child-value parameters accept one DValue construction, so scalar children do not need a wrapper:

```capy
items = dval_push(items, "first")
profile = dval_put(profile, "age", 42)
```

Container and schema-specific DValue parameters remain exact. The `dval_map` and `dval_filter` functions apply a Capy function to copied child values.

`dval_key`, `dval_keys`, and `dval_values` return copied values. `dval_get_by_path` reads nested paths, `array_merge` applies Bearer's map/list merge rules, and `dval_to_json` serializes a copied value. The DValue API pages describe each shape and fallback.

Bearer copies DValues passed to C++, another unit, a component, or a task. A change on one side does not change the other side. Native reference or alias identity never crosses this boundary.
