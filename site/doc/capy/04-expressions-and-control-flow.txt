:title
4. Expressions and control flow

:content
## Purpose

Use expressions to calculate values and control program flow. Capy evaluates expressions from left to right where the syntax lists values.

## Minimal executable example

:example capy render
function RENDER {
    var profile := {nickname: "Ada"}
    var total := {
        var price := 4
        var quantity := 3
        price * quantity
    }
    total = total + 1

    var label := if total > 10 && profile.nickname? {
        "ready"
    } else {
        "waiting"
    }

    var index := 0
    while index < 2 {
        print(index)
        index = index + 1
    }
    for number = 2..4 {
        print(number)
    }
    print("|", label, "|", total, "|", profile.nickname, "|", profile.missing?, "\n")
}

:output
0123|ready|13|Ada|false

## Output

The program writes:

```text
0123|ready|13|Ada|false
```

## Explanation

A declaration uses `:=`. Assignment uses `=` and replaces an existing local. Both expressions evaluate their right side once.

A block runs its expressions in order. Its final reachable expression is its value. The `total` block returns `price * quantity`.

An `if` with `else` returns the selected branch value. Both branches must have the same type when both can finish. An `if` without `else` has type `void`.

`while` repeats while its condition is true. `for` reads each value from an array or range. The range `2..4` is half-open. It contains `2` and `3`.

`*` runs before `+`. Comparisons produce `bool`. `&&` and `||` short-circuit, so Capy runs their right side only when needed.

Calls, indexes, and member reads bind before prefix and binary operators. `profile.nickname?` tests presence after the member read. It is true for every DValue value except `none`.

DValue reads are safe. A missing key, unusable intermediate value, negative list index, or out-of-range list index produces `none`. Reads do not change the DValue.

## Common variants

Use `break` to leave the nearest loop. Use `continue` to start its next iteration:

```capy
while true {
    break
}
```

Result: compiles.

Use brackets for a dynamic DValue key:

```capy
var key := "nickname"
print(profile[key])
```

Result: compiles.

Use `dval_require` when missing data is an error:

```capy
var nickname := dval_require(profile, "nickname")
```

Result: compiles.

## Edge cases

A condition must have type `bool`. Capy does not treat numbers, strings, or handles as conditions.

Arithmetic and comparisons require equal operand types. Integer division by zero traps.

`value?` requires a DValue. It returns false only for `none`. A key that contains `none` still exists. Use `dval_has` when you must distinguish a missing key from a present key with `none`.

Only a declared local DValue root supports nested DValue assignment. Missing, `none`, and scalar intermediate values become maps during such an assignment. An existing list accepts only an in-range nonnegative numeric selector.
