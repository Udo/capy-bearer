:title
10. Units and components

:content
Each Capy source file is an independent unit. A unit can expose `dval` functions to other units and can render named components.

## Export a function

`EXPORTS` lists the functions that another unit can call:

:example capy render
EXPORTS echo

function echo(input : dval) dval {
    -> input
}

function RENDER(request : dval) {
    var result := echo({message: "ready"})
    print(result.message, "\n")
}

:output
ready

:content
An exported function has the exact signature `(dval) dval`. Private helper functions do not appear in `EXPORTS`.

## Call another unit

Save this service as `service.capy`:

```capy
EXPORTS version

function version(input : dval) dval {
    -> {name: "Capy"}
}
```

Load and call it from a neighboring page:

```capy
function RENDER(request : dval) {
    var service := unit_load("service.capy")
    var version := service.call("version")
    print(version.name, "\n")
}
```

`unit_load` returns a request-local `module` handle. Module calls copy input and result `dval` values as BRRB. `unit_call(path, name, input)` performs the same operation without keeping a handle.

Relative paths resolve from the calling unit. Use an absolute site path when the target must not depend on the caller directory.

## Module handles

A module handle is a verified request-local capability. It can pass through typed locals, parameters, and results during that request. It cannot enter a `dval`, aggregate, closure, condition, or serialized boundary.

Do not retain a module handle for another request. A later request can load a newer valid source generation.

## Components

A component writes reusable response content. A named component uses a handler name:

```capy
function COMPONENT:CARD(request : dval) {
    var props := request.props
    <><article><?= string(props.title, "Untitled") ?></article></>
}
```

Render it into the response:

```capy
function RENDER(request : dval) {
    component_render("card.capy:CARD", {title: "News"})
}
```

Use `component_capture` when the caller needs the component output as a string. Bearer copies props into the component request context and restores the earlier props after the call.

## Boundary rules

Bearer copies `dval` values at module, component, task, export, C++, codec, request, and serialization boundaries. A target cannot mutate the caller's value through a boundary. The dynamic-values guide defines the identity rule.

Missing units, missing exports, and incompatible exported signatures are errors.
