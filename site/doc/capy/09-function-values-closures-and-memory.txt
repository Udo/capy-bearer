:title
9. Function values, closures, and memory

:content
## Function values

A function type lists its parameters and result type. A function variable needs an initializer:

```capy
function double(value : s32) s32 { value * 2 }

var transform : function(value : s32) s32 = double
print(transform(4))
```

When a function name is overloaded, the declared function type selects the matching overload. A variadic function type keeps `...` on its final parameter:

```capy
var output : function(...values : as string) void = print
output("count=", 3)
```

An anonymous function uses the `function` keyword without a name:

```capy
var increment : function(value : s32) s32 = function(value : s32) s32 {
    value + 1
}
```

You can pass function values to helpers such as `map`, `filter`, `dval_map`, and `dval_filter`. A struct field can also contain a function value.

## Closures

An anonymous function can use values from its surrounding scope. The function then becomes a closure:

```capy
function make_adder(amount : s32) (function(value : s32) s32) {
    function(value : s32) s32 {
        value + amount
    }
}

var add_ten := make_adder(10)
print(add_ten(5))
```

The closure stores each captured value. Scalars copy into the closure. Managed captures remain alive until the closure releases them. These values remain available while the closure exists. The closure does not share a mutable outer variable.

A closure can read an outer variable. It cannot assign a new value to that outer variable. Captured-closure layouts do not yet accept `s64`, `u64`, `f64`, or opaque `module` values.

## Memory management

Capy releases strings, markup, arrays, tuples, structs, and closures automatically. You do not call `free` or manage reference counts.

Assignment, function calls, returns, and block exits preserve each required value. Bearer discards all request data after a trapped request.

Avoid permanent cycles in which two managed values own each other. Reference counting cannot release a strong cycle before the request ends. Weak references are not implemented yet. Trees, lists, and other acyclic data need no special handling.
