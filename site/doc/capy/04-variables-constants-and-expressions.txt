:title
4. Variables, constants, and expressions

:content
## Declaring variables

Use `:=` to infer a variable type:

```capy
var name := "Ada"
var visits := 1
```

Inside a function, `name := value` is the shorter inferred declaration form:

```capy
message := "ready"
```

Both forms declare the name in the current lexical scope. They do not assign an existing variable.

Use `: Type =` to state the type:

```capy
var name : string = "Ada"
var started : u64 = time()
```

The compiler rejects two declarations of the same variable in one scope. A nested block can declare the same name. The nested declaration hides the outer name until the block ends.

## Assignment

Use `=` to replace the value of an existing variable:

```capy
var count := 1
count = count + 1
```

The new value must have the variable type. A declaration produces the value that it stores. An assignment also produces the stored value.

This behavior can combine a calculation and a test. Separate expressions are often easier to read.

```capy
var line := request_body()
if (line = trim(line)) != "" {
    print(line)
}
```

The compiler evaluates each initializer or right side one time. A declaration in an `if` condition remains in that function block after the condition. The conditional right side of `&&` or `||` has its own nested scope, so a declaration there does not escape.

## Constants

A top-level `const` gives a name to a compile-time `s32` literal:

```capy
const max_attempts : s32 = 3

function CLI {
    print(max_attempts)
}
```

Capy currently supports only top-level `s32` literal constants. Use a function or local variable for other values.

## Expressions and results

Calls, arithmetic, comparisons, assignments, declarations, collections, and markup produce values. `if`, loops, and ordinary blocks currently have type `void`; use assignment in their branches when later code needs a result.

A function returns its final expression when it has no explicit `return`. This function-result rule does not make every nested block a value.

Use parentheses to make precedence or tuple boundaries clear:

```capy
var total := (price + shipping) * quantity
var coordinates := (10, 20)
```
