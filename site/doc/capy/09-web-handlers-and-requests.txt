:title
9. Web handlers and requests

:content
## Purpose

Use handlers to receive a Bearer request and write its response. Each handler has a fixed name and no result value.

## Minimal executable example

:example capy render
function RENDER {
    var input := {user: {name: "Ada"}}
    var nickname := input.user.nickname
    if nickname? {
        print(string(nickname), "\n")
    } else {
        print(string(input.user.name), "\n")
    }
}

:output
Ada

## Output

The page writes `Ada` and a newline.

## Explanation

`RENDER` handles a normal HTTP page request. `CLI` handles a local CLI request. The default CLI socket is `/run/bearer/cli.sock`.

A request handler can have no parameter or one `request` parameter. A handler cannot return a value, overload, use `any`, use a variadic parameter, or use coercion.

Use `request_context()` for a copied DValue request snapshot. Use `request_context(request)` when a handler received the opaque request value. Read optional input with safe member or index access.

A missing key, an unusable intermediate value, and an invalid list index produce `none`. Use `value?` to test for `none`. Use a scalar constructor fallback such as `string(value, "guest")` when text must always exist.

Use `request_get`, `request_post`, `request_cookie`, `request_session`, `request_param`, and `request_body` for direct request reads. These string functions return an empty string when their key is absent.

Call `session_start` before session use. It restores a valid named session or creates one. Use `session_set`, `session_remove`, and `session_destroy` to change that session.

Use `response_status`, `response_header`, `response_cookie`, `redirect`, and `print` to form a response. Bearer validates response status codes and header names.

`INIT` runs after Bearer materializes a unit in a request workspace. `ONCE` runs before the first entry or component call for that resolved unit in that request. Both can run again in another request.

Bearer creates a new workspace for each request. Locals, copied DValues, module handles, and request state do not cross that boundary. A named session is separate server-side state.

## Common variants

Use a request parameter and a fallback for a normal page:

```capy
function RENDER(request : request) {
    var context := request_context(request)
    var name := string(context.params.name, "guest")
    response_header("Content-Type", "text/plain; charset=utf-8")
    print("Hello, ", name, "\n")
}
```

Result: compiles. The response depends on the request.

Use a local administration handler:

```capy
function CLI {
    print("maintenance complete\n")
}
```

Result: compiles. Bearer does not call `CLI` for a public HTTP request.

## Edge cases

This is a compile-only lifecycle example:

```capy
function INIT {
    print("unit setup\n")
}

function ONCE {
    print("request setup\n")
}

function RENDER {
    print("page\n")
}
```

Do not use `INIT` or `ONCE` for worker-local persistent state. A trap stops the current invocation. The next request starts with a new workspace.

Use `dval_require(context, "params")` only when missing input is an error. It traps for a missing key or unusable access.
