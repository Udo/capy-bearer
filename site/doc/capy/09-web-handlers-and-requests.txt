:title
9. Handling a web request

:content
A Capy Bearer handler receives one copied request snapshot. Declare every handler with `request : dval`.

## Read the request snapshot

:example capy render
function RENDER(request : dval) {
    var name := string(request.query.name, "guest")
    response_header("Content-Type", "text/plain; charset=utf-8")
    print("Hello, ", name, "!\n")
}

:output
Hello, guest!

:content
The snapshot contains `method`, `query`, `form`, `headers`, `cookies`, `body`, `files`, `route`, `url`, `server`, `session`, `props`, `config`, `call`, `connection`, `unit`, and `websocket`.

`route` contains `path`, `page`, `raw_path`, and `valid`. `url` contains `script` and `base`. `session` contains `id`, `name`, and `values`. `websocket` contains `connection_id`, `scope`, `opcode`, `binary`, and current-scope `connections`.

Missing members are `none`. Use normal conversions for scalar values. For example, use `string(request.form.email, "")`, `s32(request.websocket.opcode, 0)`, and `bool(request.websocket.binary, false)`.

## Form a response

Use `print`, `response_status`, `response_header`, `response_cookie`, and `redirect` to change the response. Use `ws_send`, `ws_send_to`, and `ws_close` for WebSocket effects. Use `request.websocket.connections` to select current-scope clients.

## Sessions

Session effects return a state map with `id`, `name`, and `values`. Keep the returned value when later code needs changed session data. The handler request snapshot does not change.

```capy
function RENDER(request : dval) {
    var session := session_start("account")
    session = session_set("theme", "dark")
    print(string(session.values.theme, ""), "\n")
}
```

## Other handlers

`RENDER`, named `RENDER`, `COMPONENT`, named `COMPONENT`, `CLI`, `WS`, `TASK`, named `TASK`, `INIT`, `ONCE`, and custom HTTP handlers all use `request : dval`. Handlers do not return application values.
