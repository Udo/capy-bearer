:title
9. Handling a web request

:content
A `RENDER` handler receives a web request and writes its response. Bearer creates a new request workspace for each invocation.

## Read a request value

:example capy render
function RENDER {
    var name := request_param("name")
    if name == "" {
        name = "guest"
    }
    response_header("Content-Type", "text/plain; charset=utf-8")
    print("Hello, ", name, "!\n")
}

:output
Hello, guest!

:content
Open the page with `?name=Ada` to change the response. `request_param` reads a query or form parameter and returns an empty string when it is absent.

## Request input

Use the narrow request functions when the program needs one value:

```capy
function RENDER {
    var query := request_get("q")
    var token := request_cookie("token")
    var body := request_body()
    print(query, token, body)
}
```

Use `request_context()` when code needs a copied dynamic snapshot of the request:

```capy
function RENDER {
    var context := request_context()
    var name := string(context.params.name, "guest")
    print(name, "\n")
}
```

Safe DValue reads return `none` for missing data. Validate all request input before use.

A handler can also receive the opaque request value:

```capy
function RENDER(request : request) {
    var context := request_context(request)
    print(string(context.params.name, "guest"))
}
```

## Form a response

`print` appends bytes to the response body. Set status and headers before the response is sent:

```capy
function RENDER {
    response_status(404, "Not Found")
    response_header("Content-Type", "text/plain; charset=utf-8")
    print("not found\n")
}
```

Use `response_cookie` for a cookie and `redirect` for a redirect response.

## Sessions

Call `session_start` before session access. Then use `session_set`, `session_remove`, and `session_destroy` to change server-side session data.

```capy
function RENDER {
    session_start("account")
    session_set("theme", "dark")
    print("saved\n")
}
```

A session persists separately from the request workspace.

## Other handlers

`CLI` handles a local CLI request. `INIT` runs when Bearer materializes a unit in a request workspace. `ONCE` runs before the first entry or component call for that unit in the request.

```capy
function CLI {
    print("maintenance complete\n")
}
```

Handlers do not return application values. A trap stops the current invocation. The next request starts with a new workspace.
