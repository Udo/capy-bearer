:title
9. Handling a web request

:content
A Capy Bearer handler receives one copied request snapshot. Declare every handler with `request : dval`.

## Read the request snapshot

:example capy render
function RENDER(request : dval) {
    var name := string(request.query.name, "guest")
    response_header("Content-Type", "text/plain; charset=utf-8")
    print("Hello, ", name, "!\n")
}

:output
Hello, guest!

:content
The snapshot contains `method`, `query`, `form`, `headers`, `cookies`, `body`, `files`, `route`, `url`, `server`, `session`, `props`, `config`, `call`, `connection`, `unit`, and `websocket`.

`route` contains `path`, `page`, `raw_path`, and `valid`. `url` contains `script` and `base`. `session` contains `id`, `name`, and `values`. `websocket` contains `connection_id`, `scope`, `opcode`, `binary`, and current-scope `connections`.

Missing members are `none`. Use normal conversions for scalar values. For example, use `string(request.form.email, "")`, `s32(request.websocket.opcode, 0)`, and `bool(request.websocket.binary, false)`.

## Form a response

Use `print`, `response_status`, `response_header`, `response_cookie`, and `redirect` to change the response. Set headers before large output. Use a redirect after a successful state change so the user can refresh the page safely.

Use `ws_send`, `ws_send_to`, and `ws_close` for WebSocket effects. Use `request.websocket.connections` to select current-scope clients.

## Handle a form

A handler normally uses one route for both the form and the POST result. Read `request.method` first. Read submitted fields from `request.form`.

This example shows the complete control flow. A GET request prints the form. A POST request validates the email, stores it in the session, queues a cookie, and redirects. Use `print` for every markup value that the handler must send. The documentation renderer runs the GET path.

:example capy render
function RENDER(request : dval) {
    response_header("Content-Type", "text/html; charset=utf-8")
    var method := string(request.method, "GET")

    if method == "POST" {
        var email := string(request.form.email, "")
        if email == "" {
            response_status(422, "Unprocessable Content")
            print(<><p>Email is required.</p></>)
            return
        }

        var session := session_start("account")
        session = session_set("email", email)
        response_cookie("has_account", "1")
        redirect("/account")
        return
    }

    print(<>
        <form method="post">
            <label>Email <input name="email" type="email" /></label>
            <button>Save</button>
        </form>
    </>)
}

:content

## Read uploaded files

Uploaded files appear in `request.files`. Each entry is a copied `dval` with the metadata that Bearer accepted for the request. Treat the original filename as user input.

Use the generated request page for the exact file fields. Validate the file count, size, and type before you store anything.

:example capy render
function RENDER(request : dval) {
    var files := request.files
    print("files=", length(files), "\n")
}

:content

## Sessions

Session effects return a state map with `id`, `name`, and `values`. Keep the returned value when later code needs changed session data. The handler request snapshot does not change.

:example capy render
function RENDER(request : dval) {
    var session := session_start("account")
    session = session_set("theme", "dark")
    print(string(session.values.theme, ""), "\n")
}

:content
