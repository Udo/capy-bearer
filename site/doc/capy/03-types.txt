:title
3. Types

:content
Capy checks types when it compiles a file. A value does not change type because another context expects a different type.

## Scalar types

Capy has these scalar types:

- `bool`: `true` or `false`
- `s32`: a signed 32-bit integer
- `s64`: a signed 64-bit integer
- `u64`: an unsigned 64-bit integer
- `f64`: a 64-bit floating-point number

An integer literal has type `s32` unless it has a suffix:

```capy
var small := 42
var signed_wide := 42s64
var unsigned_wide := 42u64
var decimal := 3.5
var scientific := 2.5e3
```

An `s32` literal must fit the signed 32-bit range. An `s64` literal must fit the signed 64-bit range. A `u64` literal accepts values through `18446744073709551615u64`. A decimal-point or exponent literal has type `f64`.

File, database, and job APIs usually return `u64` handles. Keep these handles as `u64`. A conversion through `f64` can lose precision.

## Strings and markup

Use `string` for text, paths, request values, and encoded data. A string stores bytes. Use `markup` for HTML that can compose without a second escape. A normal string does not become trusted markup automatically.

## Compound and special types

- `[T]` is an array with items of type `T`.
- A tuple has a fixed number of values and can contain different types.
- A `struct` is a named record with fixed fields.
- A `dval` is a dynamic value for Bearer APIs and unit calls.
- `function(...) Result` describes a function value.
- `void` means that a function or expression provides no value. It is not a variable or parameter type.
- Bearer supplies `request` and `module` values. A program cannot create or serialize them.

Wide scalar values work in arrays, locals, parameters, results, and function values. The current tuple, struct, and captured-closure layouts do not accept `s64`, `u64`, or `f64` fields. A `module` is opaque and cannot enter an array, tuple, struct, closure, or DValue.

## Type inference

Use `var name := value` to infer the variable type. Use `var name : Type = value` to state the type:

```capy
var count := 0
var deadline : u64 = time() + 60u64
```

Inference does not make a variable dynamic. `count` remains `s32`, and `deadline` remains `u64`.

## Type constructors

Call a type name to construct a value of that type:

```capy
var count : s32 = 12
var wide := s64(count)
var ratio := f64(wide) / 5.0
var label := string(count)
```

Primitive constructors convert numeric and Boolean values. The `string` constructors format those values as text. Boolean strings are `true` and `false`. A constructor can wrap, round, or trap.

Integer narrowing wraps. Converting a negative `s32` to `u64` sign-extends it modulo 2^64. A large `u64` can lose precision in `f64(value)`. An out-of-range or non-finite float traps in an integer constructor. Use constructor calls for explicit conversion. The former `value as Type` expression is not valid Capy.

Types have overload sets. You can add a constructor for a new source type by defining a function with the type name and result:

```capy
function string(value : User) string { value.name }
```

A coercive parameter uses the same constructor with `name : as Type`. The functions chapter explains this syntax.
