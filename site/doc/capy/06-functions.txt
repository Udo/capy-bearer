6. Functions

:content
## Declaring and calling functions

Write each parameter as `name : Type`. Put the result type after the parameter list:

```capy
function area(width : f64, height : f64) f64 {
    width * height
}

var size := area(4.0, 2.5)
```

The function returns its last expression. Use `return` to leave the function early. A `void` function may use a bare `return`:

```capy
function absolute(value : s32) s32 {
    if value < 0 { return 0 - value }
    value
}

function log_ready {
    print("ready")
    return
}
```

Capy evaluates arguments from left to right.

## Parameter conversion

A normal parameter requires its declared type. Put `as` after the colon to request conversion before the function runs:

```capy
function show(value : as string) {
    print(value)
}

show(42)       // value is "42"
show(3.5)      // value is "3.5"
show(true)     // value is "true"
```

Inside `show`, `value` has type `string`. Capy passes a string unchanged. For another type, it inserts one `string(value)` constructor call.

Overload selection prefers an exact concrete match, then an `any` specialization without construction, then a fixed-arity coercive match, and finally a variadic match. Within those groups, fewer constructor calls and a longer fixed variadic prefix win. Two equally ranked matches are ambiguous. Call the required type constructor to select one:

```capy
function show_count(count : s64) { print(count) }
show_count(s64(12))
```

## Variadic parameters

Put `...` before the final parameter name to accept zero or more trailing arguments. A variadic parameter must be last and cannot use `any`:

```capy
function join_words(...words : as string) string {
    var result := ""
    for word = words { result = result + word }
    result
}
```

Inside the function, `words` has type `[string]`. The `as` modifier constructs each non-string argument before packing the array.

Use `...` at a call to spread an array into a variadic tail:

```capy
var words := ["Capy", " ", "Bearer"]
print(...words)
```

A tuple has static arity, so it can spread into fixed parameters:

```capy
var point := (10, 20)
draw(...point)
```

A struct created by its generated field constructor can also spread its fields in declaration order. Every argument or spread source is evaluated once from left to right.

## Overloading

Several functions can have the same name when their parameter types differ:

```capy
function describe(value : s32) string { "integer" }
function describe(value : string) string { "text" }
```

The compiler selects an overload from the argument types. A result type cannot select an overload.

## Generic functions

`any` is a compile-time type parameter. `value::type` names the type supplied for that parameter:

```capy
function identity(value : any) value::type {
    value
}
```

The compiler checks each used type separately. There is no `any` value while the program runs. Each operation must support the supplied type. A generic can return `value::type` or a fixed declared result type. A function value must have a concrete function type; generic declarations are specialized at direct call sites.

After overload resolution selects a generic specialization, an error in that specialization is the call's error. The compiler does not backtrack to a weaker overload.

## Method-style calls

A function can use its first parameter as a receiver:

```capy
function doubled(value : s32) s32 { value * 2 }
print((4).doubled())
```

The compiler treats this as an ordinary receiver-first function call and evaluates the receiver once. You can also call a function stored in a struct field with dot syntax. Field lookup wins when the receiver's struct has a callable field with that name.
