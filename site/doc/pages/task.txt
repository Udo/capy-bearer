:sig
String task(String target, DValue props)

:params
target : Capy unit path. Add `:NAME` to select a named task handler.
props : Capy `dval` input available through `request.props`

:returns
opaque task ID

:see
>task
task_status
task_await
task_cancel

:content
Use `task` to place background work in the task queue. Pass a Capy unit path and a `dval` input value. The function returns an opaque task ID without waiting for the task. Use that ID with `task_status`, `task_await`, or `task_cancel`.

A target without a suffix calls `TASK`. A target with `:NAME` calls `TASK:NAME`. Each task gets a new request. Its `request.props` field contains only the copied input value. It does not receive the caller request, session, connections, resources, or memory state.

A task can later have a failed, timed out, or canceled status.

:errors
The call traps when Bearer cannot admit the task to the queue. A returned task ID only confirms admission. It does not confirm completion.

Capy handlers use `function TASK(request : dval)` or `function TASK:NAME(request : dval)`. The Capy forms are `TASK(Request& context)` and `TASK:NAME(Request& context)`.

:example capy render
var id := task("/doc/examples/task_worker.capy:STORE", {"message": "hello"})
var result := "failed"
if length(id) == 64 { result = "queued" }
print(result, "\n")
