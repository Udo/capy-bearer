:sig
String task(String target, DValue props)

:params
target : Capy unit path. Add `:NAME` to select a named task handler.
props : Capy `dval` input available through `request_context(request)["props"]`
return value : opaque task ID

:see
>task
task_status
task_await
task_cancel

:content
Use `task` to place background work in the task queue. Pass a Capy unit path and a `dval` input value. The function returns an opaque task ID without waiting for the task. Use that ID with `task_status`, `task_await`, or `task_cancel`.

A target without a suffix calls `TASK`. A target with `:NAME` calls `TASK:NAME`. Each task gets a new request. Its `request_context(request)["props"]` field contains only the copied input value. It does not receive the caller request, session, connections, resources, or memory state.

The call can fail when the queue cannot accept the task. A task can later have a failed, timed out, or canceled status.

Capy handlers use `function TASK(request : request)` or `function TASK:NAME(request : request)`. The C++ `.uce` forms are `TASK(Request& context)` and `TASK:NAME(Request& context)`.

:example capy render
var id := task("/doc/examples/task_worker.capy:STORE", dval({"message": "hello"}))
var result := "failed"
if length(id) == 64 { result = "queued" }
print(result, "\n")

:example cpp render
DValue props; props["message"] = "hello";
String id = task("/doc/examples/task_worker.capy:STORE", props);
print(id.size() == 64 ? "queued\n" : "failed\n");
