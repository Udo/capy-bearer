:sig
String task(String target, DValue props)

:params
target : unit path with an optional `:NAME` task handler
props : copied structured input available as `context.props`
return value : opaque task ID

:see
>task
task_status
task_await
task_cancel

:content
Enqueues a named Bearer task and returns immediately with an opaque ID. `worker.capy` invokes its default `TASK` handler; `worker.capy:refresh` invokes `TASK:refresh`. The configured dedicated task workers process the bounded durable queue independently of request workers.

Each invocation receives a fresh ordinary `Request`. The copied DValue is available only as `context.props`; request, session, connection, resource, and caller memory state are not inherited. Queue admission never compiles the target or forks a process. Missing handlers, compilation errors, traps, timeouts, cancellation, and worker loss become isolated task status outcomes.

Capy handlers use `function TASK(request : request)` or `function TASK:NAME(request : request)`. C++ handlers use `TASK(Request& context)` or `TASK:NAME(Request& context)`.

:example capy render
var id := task("/doc/examples/task_worker.capy:STORE", dval({"message": "hello"}))
var result := "failed"
if length(id) == 64 { result = "queued" }
print(result, "\n")

:example cpp render
DValue props; props["message"] = "hello";
String id = task("/doc/examples/task_worker.capy:STORE", props);
print(id.size() == 64 ? "queued\n" : "failed\n");
