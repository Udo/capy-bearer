:content
`function RENDER` defines the Capy HTTP page entrypoint.

Use `function RENDER { ... }` for the normal form. You can also declare `function RENDER(request : request) { ... }`. The optional input is an opaque Capy request value. The handler returns no value. Print response content and use Capy request and response functions in the body.

Bearer calls `RENDER` for a direct HTTP request to the unit. `ONCE` runs before the first render or component entrypoint for the unit and request. `INIT` runs when a worker loads the unit. A direct page request has no component props.

Use `COMPONENT` or `COMPONENT:NAME` for reusable component output. Component helpers do not call `RENDER`. A unit can define `RENDER`, `COMPONENT`, and `WS` together. In that case, `RENDER` serves HTTP and `WS` handles later WebSocket messages.

The compiler rejects other parameter forms, a return type, and handler overloads. A trap in `RENDER` stops that request invocation.

## C++ API

C++ declares `RENDER(Request& context)`. It receives live parameters, cookies, POST data, session state, headers, uploaded files, and component props. `unit_render(file_name, context)` passes that live context to the callee.

Capy does not expose C++ `Request&`, mutable request fields, or C++ object layouts. Use Capy request functions and copied `dval` values. Capy cannot use C++ references or direct C++ object access.
