:sig
pid_t server_start_http(String key, String socket_fn_or_port, String call_bearer_filename, String call_function = "")

:params
key : runtime-wide listener key
socket_fn_or_port : TCP port number or Unix socket path
call_bearer_filename : `.capy` or `.uce` file that contains the handler
call_function : optional named handler
return value : listener process PID, or `0` if Bearer cannot start it

:see
>sys
server_stop
task

:content
In Capy, this function starts or updates a custom HTTP listener. It supports custom HTTP listeners only.

The key identifies one runtime-wide listener. A second call with the same key and bind target updates the handler without a restart. A changed bind target stops the old listener and starts another one.

Pass a numeric TCP port such as `"19091"` or a Unix socket path. Bearer accepts handler files only below its configured custom-server root. Runtime settings also limit ports, socket paths, and listener count.

A Capy handler file uses `SERVE_HTTP`:

```capy
function SERVE_HTTP {
    response_header("Content-Type", "text/plain; charset=utf-8")
    print("hello from custom HTTP\n")
}

function SERVE_HTTP:admin {
    print("named handler\n")
}
```

The handler can read normal request data. A long-running handler delays its listener.

The paired example starts the existing C++ `examples/sample_unit.uce` handler. Pass a `.capy` path and an empty handler name to call its default `SERVE_HTTP` handler.

:example capy render
var pid := server_start_http("doc-demo-server", "/tmp/bearer/custom-servers/doc-demo.sock", "examples/sample_unit.uce", "RENDER")
if pid > 0 { print("custom HTTP server started\n") } else { print("start failed\n") }
server_stop("doc-demo-server")

:example cpp render
pid_t pid = server_start_http("doc-demo-server", "/tmp/bearer/custom-servers/doc-demo.sock", "examples/sample_unit.uce", "RENDER");
print(pid > 0 ? "custom HTTP server started" : "start failed", "\n");
server_stop("doc-demo-server");
