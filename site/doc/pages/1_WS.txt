:content
`function WS(request : dval)` defines the Capy WebSocket message handler.

Every Capy Bearer handler has exactly one parameter. The parameter name is `request`. Its type is `dval`. The value is a copied request snapshot. `request.body` contains the current message payload. `request.websocket.connections` contains current-scope connection IDs.

Read input from the request fields. Use response, session, output, and WebSocket functions for effects. The compiler rejects zero parameters, other parameter types, extra parameters, return types, and handler overloads.

C++ declares `WS(Request& context)`. It reads the payload from `context.in`, metadata from `context.params["WS_..."]`, and persistent connection state from `context.connection`. The connection value starts empty and persists for later calls on that socket.

:example capy render
print(string(request.method, ""), "\n")

:example cpp render
print(context.params["REQUEST_METHOD"], "\n");
