:title
Configurable Error Pages

:sig
page_compiling=site/errors/compiling.uce
page_compiler_error=site/errors/compiler-error.uce
page_runtime_error=site/errors/runtime-error.uce

:params
page_compiling : page rendered with status 503 while a requested page builds
page_compiler_error : page rendered with status 500 when a requested page fails to build
page_runtime_error : page rendered with status 500 after a recovered fault or uncaught exception

:see
>runtime
0_Request
0_DValue
2_Request_set_status

:capy-status cpp-specific

:content
Capy cannot configure Bearer error pages. Configure these C++ runtime settings in `/etc/bearer/settings.cfg` instead.

Set each optional key to a `.uce` error page path. The path can be absolute or relative to the server working directory. Bearer uses built-in plain text when a key is unset, missing, or fails.

Each error page receives error data in `context.call["error"]`. It includes `type` and `source`. Compiler errors also include compiler output, generated C++, status, and details. Runtime errors also include title, details, request URI, signal data, trace, and generated C++.

`page_compiling` returns status 503 while proactive compilation builds a requested page. `page_compiler_error` returns status 500 after an entry page fails to build. `page_runtime_error` returns status 500 after a recovered fault or uncaught exception.

An error page can change the status and headers. Keep runtime error pages simple. Bearer uses built-in output if an error page fails, so error pages cannot recurse.
