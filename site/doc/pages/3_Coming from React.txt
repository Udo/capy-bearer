Capy uses typed `function RENDER` units. Capy has no C++ template-preprocessor workflow.

This page describes the C++ Bearer workflow. Bearer renders on the server. It does not provide a client-side virtual DOM or a required file router.

## C++ concept map

`RENDER(Request& context)` renders a page. `COMPONENT(Request& context)` and `COMPONENT:NAME(Request& context)` render reusable server components. `context.props` holds component input.

`context.call` holds request-local shared state. `context.cfg` holds structured app data. `ONCE(Request& context)` prepares one unit for a request. `INIT(Request& context)` prepares a loaded worker unit.

Use `<?= expression ?>` for escaped text. Use `<?: expression ?>` only for trusted markup. `component()` returns component HTML. `unit_render()` renders another page unit.

## Routes and data

Keep routing in a front controller when that fits the app. The starter example checks page files and parent index handlers. This keeps route rules visible in application code.

Use collection helpers for short transformations. Use explicit loops when the work has side effects or several steps.

## What Bearer does not provide

Bearer does not provide a global asset registry or island registry. It does not require JSX-like component tags. C++ components do not have built-in child or slot syntax. Pass explicit props and call components instead.

## Debugging

Check generated C++ under `BIN_DIRECTORY` when a C++ unit does not compile. Bearer reports the source path and compiler output.
