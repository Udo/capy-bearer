Capy server components

Capy uses typed `function RENDER` units. Bearer renders on the server. It does not require a client-side virtual DOM or file router.

## Concept map

`function RENDER(request : dval)` renders a page. `function COMPONENT(request : dval)` renders reusable server content. A named component uses `function COMPONENT:NAME(request : dval)`. Read component input from `request.props`.

`request.call` holds request-local shared state. `function ONCE(request : dval)` prepares a unit for one request. `function INIT(request : dval)` prepares a loaded unit worker.

Use markup literals for escaped output. Use `component()` when code needs component output as a value. Use `component_render()` or `unit_render()` when code writes directly to the response.

## Routes and data

Keep routing in a front controller when it fits the application. The starter example checks page files and parent index handlers. This keeps route rules visible in application code.

Use collection helpers for short transformations. Use explicit loops when work has effects or several steps.

## What Bearer does not provide

Bearer does not provide a global asset registry or island registry. It does not require JSX-like component tags. Capy components do not have built-in child or slot syntax. Pass explicit props and call components instead.

## Debugging

Check the compiler output under `BIN_DIRECTORY` when a Capy unit does not compile. Bearer reports the source path and compiler output.
