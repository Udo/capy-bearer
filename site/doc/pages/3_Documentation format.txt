:title
Documentation format

:params
- `:sig` — one or more real C++ `.uce` signatures, exactly as declared
- `:params` — `name : description` rows plus `return value : description`
- `:content` — usage-first prose in 2-5 tight sentences
- `:example capy render` — a Capy example, immediately followed by its C++ equivalent
- `:example cpp render` — its equivalent C++ `.uce` example
- `:see` — an area reference (`>area`) followed by closest sibling page slugs


:content
API pages live in `site/doc/pages/`; ordered Capy language-guide articles live in `site/doc/capy/`. Both use one parser, renderer, detail layout, search, single-page view, and runtime gate. Language articles require `:title` and `:content`; API pages additionally follow the manifest-driven paired-example rules below.

Each applicable API page shows separate Capy and C++ `.uce` declarations. `capyc` extracts Capy declarations from `src/capy/stdlib.capy`; compiler primitives and handlers use a small checked catalog. The page's `:sig` section supplies the existing C++ `.uce` declaration. Unsupported and C++-specific pages show their status instead of a fabricated Capy signature.

Doc pages use one structured text format shared by the index, detail view, single-page view, search, and tests. A typed example is exactly two contiguous blocks: `:example capy ENTRY`, then `:example cpp ENTRY`, where ENTRY is one of `render`, `cli`, `component`, `init`, `once`, or `ws`; the entries must match. Unknown, reversed, or unpaired typed blocks are rejected. During the migration, bare `:example` remains a legacy C++ render block and is visible to the checker, but new examples must use typed pairs.

Render pairs compile and execute through their actual Capy and C++ units, must produce exactly equal output, and show each language's source and output or error. Other entries compile their real handler but are explicitly compile-only: documentation never fakes a CLI, component, lifecycle, or WebSocket invocation. Keep examples self-contained and deterministic.

:example capy render
print("A doc page normally contains :sig, :params, :content, :example, and :see.\n")
print("Examples must print deterministic output.\n")

:example cpp render
print("A doc page normally contains :sig, :params, :content, :example, and :see.\n");
print("Examples must print deterministic output.\n");
