Capy has no C++ preprocessor API. Use Capy `function RENDER` units instead.

This page describes the C++ Bearer preprocessor. It converts a C++ `.uce` or `.ws.uce` source file to generated C++ before compilation.

## Normal use

Use `<> ... </>` or `?> ... <?` for literal output. Use `<? ... ?>` for C++ code inside literal output. Use `<?= expression ?>` for HTML-escaped output. Use `<?: expression ?>` only for trusted output that needs no HTML escaping.

Use `#load "other.uce"` to include another unit while Bearer compiles the source. Use `unit_render()` or `unit_call()` when the unit must run at request time.

## C++ handlers

C++ units can define `RENDER(Request& context)`, `COMPONENT(Request& context)`, `CLI(Request& context)`, `ONCE(Request& context)`, `INIT(Request& context)`, or `WS(Request& context)`. `INIT` runs when Bearer loads the unit for a worker. `ONCE` runs before the first render or component call for that unit and request.

`COMPONENT:NAME(Request& context)` defines a named component. `EXPORT` records a declaration for unit metadata.

## Generated files and errors

Bearer writes generated C++ under `BIN_DIRECTORY`. It then compiles that file to a WebAssembly unit. Check the generated C++ first when a unit does not compile.

Compile errors report the source path and compiler output. A C++ error stops the affected request or prevents the unit from loading.

## Limits

The preprocessor is not a full C++ parser. Keep template delimiters out of C++ strings and comments when possible. A bad `#load` target also prevents the including unit from compiling.

:example cpp render
// The preprocessor lets you mix C++ logic with output. Code generates markup:
StringList items = split("apples,pears,plums", ",");
String html = "";
items.each([&](String item) { html += "<li>" + item + "</li>"; });
print(html, "\n");
