:sig
function component_exists(name : string) bool

:params
name : a component path, optionally followed by `:HANDLER`

:returns
`true` when Bearer resolves the name to a component source file, otherwise `false`.

:content
`component_exists()` runs the same name resolution that `component()` and `component_render()` use, and reports whether it found a file. It renders nothing and runs no handler.

Use it to make a component optional. Without the guard, a missing component sets the response status to `500` and writes a banner element into your page; with it, you choose the fallback.

## What the check does and does not cover

It resolves the **file**. A `:HANDLER` suffix is ignored for the purpose of this check, so `component_exists("widgets.capy:CARD")` answers "does `widgets.capy` exist", not "does it define `COMPONENT:CARD`". A name whose file exists but whose named handler does not will pass this check and then fail at render time.

It also does not compile the component. A file that exists but does not compile returns `true` here and reports its compile error when it is rendered.

Resolution is unchanged from `component()`: `.capy` is appended when absent, a leading `/` is tried as a real path and then as a site-root path, and a relative name is tried against the entry unit's directory, the calling unit's directory, and the site root, in that order.

:example capy render
if component_exists("/doc/examples/card.capy") { print("exists\n") } else { print("missing\n") }

:example capy render fall back when a theme fragment is absent
if component_exists("/doc/examples/card.capy") {
    component_render("/doc/examples/card.capy:CARD", {title: "Themed"})
} else {
    print("<p>Default header</p>")
}
print("\n")

:example capy render pick the first component that resolves
var candidates := ["/doc/examples/missing.capy", "/doc/examples/card.capy"]
for candidate := candidates {
    if component_exists(candidate) {
        print(candidate, "\n")
    }
}
