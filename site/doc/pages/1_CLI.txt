`function CLI` defines the local command entrypoint for a Capy unit.

Use `function CLI { ... }` for the normal form. You can also declare `function CLI(request : request) { ... }`. The optional `request` is an opaque Capy value. It is not a C++ `Request&`.

The handler accepts no other inputs and returns no value. The body can print output and call Capy request functions such as `cli_input()` and `cli_arg()`. `cli_input()` returns a copied `dval`. `cli_arg()` returns a string value.

Bearer calls `CLI` only through its local CLI Unix socket. It does not call `CLI` for a public HTTP request. Use this handler for local tests, migrations, maintenance, and administration.

The default socket path is `/run/bearer/cli.sock`. Set `CLI_SOCKET_PATH` to change it. The `scripts/bearer-cli` helper sends `key=value` input as a JSON POST body by default. Use `--get` for a query-string request.

A Capy declaration fails to compile if it has a non-`request` parameter, more than one parameter, or a return type. A trap in the handler stops that invocation.

`ONCE` runs before `CLI` for the unit. `INIT` runs when a worker loads the unit.

## C++ API

C++ declares `CLI(Request& context)`. Its live `context` provides query, POST, body, parameter, header, and response access. C++ can test `context.params["BEARER_CLI"]` and read `context.params["SCRIPT_FILENAME"]`.

Capy does not expose the C++ `Request&` layout or its mutable `DValue` aliases. Use the Capy request functions and copied `dval` values instead.

:example capy render
print("CLI is a unit directive; place it at top level in a .uce unit.\n")

:example cpp render
print("CLI is a unit directive; place it at top level in a .uce unit.\n");
